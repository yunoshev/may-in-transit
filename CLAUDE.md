# Maya in Transit — вики мира

Локальная вики мира для будущего сериала-влога: одна женщина, Майя, летит к Юпитеру в 2050-х на вращающемся одноместном корабле с бортовым ИИ ARI и ведёт влог. Здесь собираем мир: лор, Землю 2050-х, миссию, корабль, персонажей, науку с расчётами, оценку реалистичности.

**Узкий спек.** Мы собираем мир. Не делаем сам влог, сценарии, Blender-сцены, рендер. Раздел `70-series` хранит производственные материалы из исходников как есть и не развивается, пока не скажут.

**Цель графики.** Схематичные чертежи-blueprint, максимально чистые и согласованные. Не физически точная инженерия, а канон визуала: по ним потом моделируют и рендерят, им следуют без самодеятельности. Принцип из исходников: к началу моделирования художник не изобретает корабль, а строит уже определённую машину.

## Порядок работы: сверху вниз
1. Скелет: все страницы-заготовки, разделы, перекрёстные ссылки. Согласовать с пользователем.
2. Углубление по разделам, сверху вниз внутри раздела (общее → частное). Каждый раздел после углубления согласуется с пользователем.
3. Новое знание — сразу перекрёстные ссылки в обе стороны. Изолированных страниц нет.
4. Решения записываются в `ru/90-reference/decisions.md`, противоречия — в `contradictions.md`, вопросы к пользователю — в `open-questions.md`.

## Иерархия канона
При расхождении побеждает (сверху вниз):
1. новейшее явное решение пользователя (`decisions.md`);
2. спецификация корабля (`sources/maya_ari_ship_3d_build_spec.md`);
3. документация миссии и физики;
4. концепция сериала (`sources/space_vlog_series_concept_v2.md`);
5. заметки к отдельным эпизодам.

`sources/` — исходный архив, **никогда не редактируется**. `space_vlog_series_concept.md` (v1) целиком входит в v2; ссылаться на v2.

## Имена и ссылки
- Файлы и папки — нормальные английские слова через дефис: `habitat-pod.md`, `life-support.md`. Не транслит. Не переименовывать без нужды: имя файла — стабильный идентификатор для перевода.
- В каждом разделе и подразделе есть `index.md` — оглавление со ссылками на все страницы раздела.
- Ссылки — **только относительные markdown-ссылки**, не `[[wikilinks]]`: `[Жилой модуль](../30-ship/habitat/pressure-vessel.md)`. Якорь на раздел: `(file.md#заголовок)`. Такие ссылки одинаково работают в `ru/` и `en/`.
- Картинки: `![Подпись](../../assets/ship/ship-overview.svg)` — тоже относительный путь.
- Ссылки на исходники — в поле `sources` шапки и в блоке «Основания», вида `sources/maya_ari_ship_3d_build_spec.md §11`.

## Шапка страницы
```yaml
---
title: Отсек стазиса, сна и укрытия
aliases: [stasis shelter, SLEEP / MED / SAFE, укрытие]
type: system        # section | concept | system | zone | component | entity | person | org | place | event | episode | reference
status: draft       # draft | proposed | canon | frozen
realism: 3          # 1–5, ставится после оценки; до оценки поле не пишем
sources:
  - sources/maya_ari_ship_3d_build_spec.md §11
tags: [ship/habitat]
---
```
- `title` — русский. `aliases` — английские названия и русские синонимы (по ним ищет Obsidian).
- Статусы: `draft` — набросок агента; `proposed` — готово к согласованию; `canon` — пользователь согласовал; `frozen` — заморожено для моделирования, менять только через запись в `decisions.md`.
- Только пользователь переводит страницу в `canon` и `frozen`.

## Тело страницы
```markdown

Кратко: 1–3 предложения — что это и зачем существует.

## …смысловые разделы…

## Связи
- [Страница](путь.md) — чем связана

## Основания
> [!verified] Проверено
> Факт реального мира + источник (URL или sources/…).

> [!fiction] Вымысел
> Допущение мира 2050-х.

> [!production] Решение для производства
> Выбор ради визуала, согласованности, стоимости.

> [!realism] Реализм: 4/5
> Почему такая оценка.

## Открытые вопросы
- …
```
Служебные блоки: `[!conflict]` — противоречие (дублируется в `contradictions.md`), `[!open]` — открытый вопрос внутри текста.

**Шкала реализма:** 5 — соответствует сегодняшней инженерии; 4 — правдоподобная экстраполяция к 2050-м; 3 — нужен прорыв, но физике не противоречит; 2 — натяжка, держится на допущениях; 1 — противоречит физике.

## Язык и стиль
- Текст — русский, живой и плотный, без воды. Это энциклопедия мира, а не реклама.
- Технические термины: русский термин, при первом упоминании на странице английский в скобках — «система жизнеобеспечения (ECLSS)». Пары терминов — в `ru/90-reference/glossary.md`; глоссарий — словарь для будущего перевода.
- Единицы СИ, русские сокращения: м, м/с², об/мин, км/с. Десятичная запятая: 0,5 g.
- Надписи на корабле, метки интерфейса, реплики героев из исходников — по-английски, как в исходниках (`POTABLE H2O`, `SLEEP / MED / SAFE`).

## Числа
- Каждое каноническое число живёт в `data/canon.yaml` (одно место). Производные величины считают скрипты в `calc/`.
- В тексте число привязывается так: `<span data-canon="habitat.floor_radius">28 м</span>`. `tools/` синхронизирует текст с `canon.yaml` и ловит расхождения.
- Не придумывать орбитальные числа на глаз: расстояния, скорости, периоды, даты, угловые размеры — только расчётом или с источником.

## Графика
Источники:
1. **Код** (`calc/`, `figures/`): графики расчётов, орбиты, схемы Mermaid, SVG-чертежи с размерами и подписями. Размеры берутся из `canon.yaml`, не вписываются руками. Подписи — из таблицы строк, сборка даёт `name.ru.svg` и `name.en.svg`.
2. **anatomy** (`.claude/skills/anatomy`): изометрические виды корабля и узлов, разнесённые виды, разрезы. Исходник — `figures/<name>/build.mjs`, геометрия читает `data/canon.json`. Подписей на рисунке нет — легенда с номерами в тексте страницы.
3. **ИИ-картинки** (вручную через пользователя или автоматически через API): атмосфера и внешний вид. Без текста на изображении. Рядом файл `name.meta.yaml`: инструмент, промпт, дата, ревизия канона.
- Каждую картинку перед вставкой проверять глазами на соответствие канону.
- **Схема стоит там, где о ней рассказывает текст:** абзац про оси — рядом рисунок осей, про план — план. На страницах корабля чертёж «где это» идёт сразу под «Кратко». Отдельный раздел «Чертёж» внизу страницы не делать.
- **Никаких ASCII-схем в блоках кода.** Геометрия — чертёж из кода; связи, потоки, подчинение — Mermaid прямо в странице (Obsidian и сайт рисуют его сами). Блок кода — только для настоящего кода и шаблонов записей.
- Все листы собраны на странице [Чертежи](ru/90-reference/drawings.md); новый лист добавлять туда же.

## Агенты
- Основная сессия — главред: структура, решения, сведение, ответы пользователю.
- Исполнители — саб-агенты: `model: sonnet` по умолчанию, `opus` для сложного (изобретение мира, расчёты, аудит реализма). Модель указывать явно.
- Параллельные агенты делят работу по папкам — двое не пишут в один файл.
- WebSearch ограничен — опираться на WebFetch известных страниц (NASA, ESA, JPL, peer-review).

## Сборка
- `uv run tools/build.py` — пересчитать производные, переписать числа в спанах, свод значений, все чертежи и графики, затем проверки. Запускать после любой правки `data/canon.yaml`, `data/strings.yaml`, `calc/` или `figures/`.
- `uv run tools/build.py --watch` — то же при каждом сохранении; удобно держать открытым рядом с Obsidian.
- Сайт при публикации пересобирает всё сам (`--no-verify`), но в git должны лежать актуальные SVG — их видит Obsidian.

## Проверки (запускать после каждой волны правок)
- `uv run tools/lint.py` — битые ссылки и картинки, шапки, страницы-сироты, отсутствие в оглавлении раздела.
- `uv run tools/canon_sync.py --check` — числа в тексте совпадают с `canon.yaml`.
